# 11. ACCESS TOKEN

Access Token sử dụng JWT.

Thời gian mặc định:

15 phút.

Payload tối thiểu:

sub = user id
sid = auth session id
type = access
iat

Không đưa:

password

vào JWT.

Frontend giữ Access Token trong MEMORY.

KHÔNG lưu Access Token trong:

localStorage

Protected request sử dụng:

Authorization: Bearer <access_token>

# 12. REFRESH TOKEN

Refresh Token:

- là token ngẫu nhiên có entropy cao
- không cần là JWT
- không lưu plaintext trong database

Database chỉ lưu:

SHA-256 hash của refresh token.

Refresh token thật chỉ tồn tại:

- phía client dưới dạng HttpOnly Cookie
- trong thời gian request


Cookie:

HttpOnly = true

SameSite = Lax

Secure:
- false ở local development
- true ở production

Path:

/api/v1/auth


Refresh Token lifetime mặc định:

7 ngày.

# 14. REFRESH TOKEN ROTATION

Mỗi lần gọi refresh:

1. Backend đọc refresh token từ HttpOnly Cookie.
2. Hash token.
3. Tìm auth session.
4. Kiểm tra:
   - session tồn tại
   - chưa revoke
   - chưa hết hạn
   - User tồn tại
   - User ACTIVE
5. Tạo refresh token mới.
6. Update hash mới cho session.
7. Refresh token cũ mất hiệu lực.
8. Tạo Access Token mới.
9. Set refresh cookie mới.

Không tạo session mới sau mỗi refresh.


---

# 15. KHÔI PHỤC AUTH SAU KHI RELOAD

Vì Access Token chỉ nằm trong memory nên sau khi F5:

Access Token sẽ mất.

Frontend phải:

Application start
↓
POST /api/v1/auth/refresh
↓
Browser tự gửi HttpOnly refresh cookie
↓
Backend xác thực session
↓
Trả Access Token mới
↓
GET /api/v1/users/me
↓
Auth state được khôi phục

Nếu refresh thất bại:

Frontend chuyển về trạng thái Guest.

Không coi đây là application error nghiêm trọng.

# 16. LOGOUT

UC03 yêu cầu kết thúc phiên xác thực hiện tại.

Logout phải:

1. Xác định current auth session.
2. Set revoked_at cho session.
3. Xóa refresh cookie.
4. Frontend xóa Access Token khỏi memory.
5. Xóa User state.
6. Điều hướng đến /login.

Không được chỉ:

localStorage.removeItem(...)

rồi coi như logout.

# 17. ACCOUNT LOCKED

UC02 yêu cầu tài khoản bị LOCKED không được đăng nhập.

Login:

Nếu password đúng nhưng:

status = LOCKED

Backend từ chối authentication.


Refresh:

Nếu account đã bị chuyển sang LOCKED:

refresh request cũng phải bị từ chối.

Protected API:

Authentication dependency phải kiểm tra User vẫn tồn tại và đang ACTIVE.

Điều này chuẩn bị cho UC42 ở giai đoạn Admin sau này.

# 18. CHANGE PASSWORD

UC05 yêu cầu:

- current_password
- new_password
- confirm_new_password

Luồng Backend:

1. Authenticate current user.
2. Verify current_password.
3. Validate new password policy.
4. Kiểm tra confirm password.
5. Kiểm tra new password khác current password.
6. Hash new password.
7. Update users.password_hash.
8. Revoke tất cả auth session khác của User.
9. Giữ current session tiếp tục hoạt động.
10. Thông báo thành công.

Không trả password hoặc password_hash trong response.

# 39. CSRF DECISION

Access authentication sử dụng Authorization Header,
không sử dụng access cookie.

Refresh token nằm trong SameSite HttpOnly Cookie.

Logout yêu cầu cả authenticated Access Token.

Vì vậy Phase 1 chưa thêm CSRF library riêng.

Nếu sau này chuyển toàn bộ authentication sang cookie-based,
phải đánh giá lại CSRF.
